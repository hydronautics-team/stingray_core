# Stingray Core Doctor

`stingray_core_doctor` — инструмент оператора для предварительной диагностики
аппарата. Он только собирает и отображает результаты проверок. Doctor не
управляет состоянием аппарата и не должен запускать, останавливать,
перезапускать или перенастраивать рабочие ROS-ноды.

Безопасность аппарата не должна зависеть от того, запущен ли процесс doctor.

## Назначение

Doctor отвечает на два вопроса:

1. Готовы ли компьютер, ROS-окружение и конфигурация к запуску программного
   комплекса?
2. Какие данные публикует уже запущенная система?

Doctor не принимает решение о том, можно ли включать движители. Окончательное
решение о готовности аппарата, доступных режимах и разрешении `arm` должен
принимать отдельный supervisor.

## Разделение ответственности

| Компонент | Ответственность |
|---|---|
| Driver / adapter | Связь с устройством, проверка измерений и диагностика своего компонента |
| Localization | Достоверность оценки состояния, инновации и ковариация фильтра |
| Supervisor | Готовность аппарата, доступные возможности, разрешение `arm`, деградированные режимы и реакция на отказы |
| Doctor | Предстартовые проверки компьютера и отображение состояния работающей системы |

Главное правило:

```text
Doctor сообщает о состоянии.
Supervisor принимает решения и выполняет действия.
```

## Режимы работы

### Предстартовая проверка компьютера

```bash
ros2 run stingray_core_doctor stingray_core_doctor preflight
```

Режим `preflight` проверяет:

- версию ROS 2;
- наличие sourced workspace;
- `ROS_DOMAIN_ID`;
- наличие необходимых ROS-пакетов;
- соответствие требованиям среды запуска, например Docker.

Этот режим не запускает драйверы, не открывает устройства и не изменяет
состояние ROS-графа.

Результат `preflight` означает только, что программный комплекс можно
попытаться запустить. Успешный `preflight` не означает, что аппарат готов к
`arm`.

### Наблюдение работающей системы

```bash
ros2 run stingray_core_doctor stingray_core_doctor online
```

Режим `online` выполняет те же проверки окружения и дополнительно наблюдает за
уже запущенными потоками IMU, DVL и датчика глубины.

Он не запускает и не останавливает ноды. В текущем виде это переходный
интерфейс. После появления supervisor режим `online` должен в первую очередь
отображать опубликованные supervisor сведения о готовности и диагностические
сообщения компонентов, а не повторять его правила внутри doctor.

### Загрузка конфигурации

```bash
ros2 run stingray_core_doctor stingray_core_doctor --config path-to-yaml
```

Необязательный параметр `--config`, который изменяет используемый файл конфигурации. 
Файл по умолчанию расположен по следующему пути:
```text
welt_rov/
└── src/
    ├── welt_bringup/
    ├── welt_config/
    │   └── diagnostics/
    │       └── doctor.yaml
    └── stingray_core/
        └── src/
            └── stingray_core_doctor/
```


## Что doctor не должен делать

Doctor не должен:

- запускать sensor-only или production launch-файлы;
- посылать сигналы рабочим ROS-процессам;
- запускать или перезапускать драйверы;
- принимать решение о разрешении `arm`;
- переводить аппарат в деградированный режим;
- реализовывать политику восстановления компонентов;
- отправлять команды движителям;
- заменять отсутствующее измерение нулём;
- реализовывать навигационный фильтр;
- отбрасывать измерения вместо localization;
- выполнять системную реакцию на отказ.

## Порядок запуска аппарата

Предполагаемая последовательность:

```text
1. Doctor проверяет компьютер и конфигурацию.
2. Основной launch запускает drivers, adapters, localization и supervisor.
3. Каждый компонент публикует свою диагностику.
4. Supervisor определяет готовность и доступные режимы.
5. Doctor показывает результат оператору.
6. Оператор отдельно выполняет arm.
```

Даже после успешной проверки система должна оставаться в состоянии
`DISARMED`, пока оператор явно не разрешит включение движителей.

## Коды завершения

- `0` — все выполненные проверки завершились успешно;
- `1` — обнаружено одно или несколько предупреждений;
- `2` — одна или несколько проверок завершились ошибкой.

Эти коды описывают результат doctor, но не заменяют состояние готовности,
публикуемое supervisor.
